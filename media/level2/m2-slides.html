Unstructured search

A black box answers one question: f(x) = 1 if x is the marked item, 0 otherwise. Nothing about x tells you where to look next.

Classically you test items one at a time: about N/2 queries on average, up to N in the worst case. Grover's search needs about (π/4)√N.

A phase oracle marks with a sign

Zf|x⟩ = (−1)f(x)|x⟩

It multiplies the marked amplitude by −1 and leaves the others alone. The probabilities do not change: measuring right after the oracle tells you nothing.

Module 2 · Grover's search4

Building an oracle for any string

  1. X on every qubit whose bit is 0: |w⟩ becomes |11...1⟩.
  2. A multi-controlled Z: flips the sign of |11...1⟩ only.
  3. The same X gates again: |11...1⟩ becomes |w⟩.

Bit order as in Qiskit: in "01" the rightmost bit is qubit 0. For w = 01 the X gates go on qubit 1. In code, the bit for qubit q is marked[n - 1 - q].

zeros = [q for q in range(n) if marked[n - 1 - q] == "0"]
qc.x(zeros); mcz(qc, range(n)); qc.x(zeros)

Pause and predict

You want the oracle for w = 110 on 3 qubits. Which qubits get X gates?

Only qubit 0. Reading "110" from the right: qubit 0 has bit 0, qubit 1 has bit 1, qubit 2 has bit 1. The X on qubit 0 turns |110⟩ into |111⟩, the multi-controlled Z flips its sign, and the second X turns it back.

Flips the sign of |11⟩.

3 qubits

Flips the sign of |111⟩.

Any n

qc.h(t)
qc.mcx(controls, t)
qc.h(t)

H X H = Z turns the multi-controlled X into a multi-controlled Z.

It does not matter which qubit is the target: a multi-controlled Z treats all its qubits the same way. The lab's helper mcz(qc, qubits) picks the right form.

The diffuser: reflection about the mean

a → 2·m − a

m is the mean (average) of all the amplitudes. Each amplitude ends up as far on the other side of m as it started. The marked amplitude, pushed below zero by the oracle, jumps far above the rest.

Example: 0.5, 0.5, −0.5, 0.5 has mean 0.25 and becomes 0, 0, 1, 0.

Module 2 · Grover's search8

The diffuser circuit

As a matrix the diffuser is 2|s⟩⟨s| − I, with |s⟩ the equal superposition. The circuit:

H on all → X on all → multi-controlled Z → X on all → H on all
  • H and X turn |s⟩ into |11...1⟩, so the multi-controlled Z flips the sign of |s⟩ and nothing else.
  • That gives I − 2|s⟩⟨s|: the diffuser times −1. A factor −1 on the whole state is invisible to every measurement; Qiskit's Grover operator has it too.

The geometric picture

The state stays in a plane: |w⟩ (the marked state) and |w⊥⟩ (the equal superposition of the others).

It starts at angle θ from |w⊥⟩, with sin θ = √(s/N) for s marked items. The oracle and the diffuser are two reflections, and two reflections make a rotation: each iteration turns the state by 2θ.

Module 2 · Grover's search11

How many iterations?

After t iterations the angle is (2t + 1)θ, so

P(success) = sin²((2t + 1)θ)
  • Aim for (2t + 1)θ close to 90°: take t = ⌊π/(4θ)⌋, about (π/4)√(N/s).
  • N = 8, one marked: θ ≈ 20.7°, t = 2, P = 0.9453. Not exactly 1, because 5θ ≈ 103.5° overshoots 90° a little.
  • For large N the success probability at the best t is close to 1 (at least 1 − s/N).
Module 2 · Grover's search12

Running too long makes it worse

Past the best t the state rotates beyond |w⟩, and the success probability falls: 0.9453 at t = 2, 0.3301 at t = 3, 0.0122 at t = 4.

It comes back later (0.9998 at t = 6), but that costs three times as many oracle calls.

Exact values for N = 8 (lab Step 6).

Pause and predict

N = 4 with one marked item. How many iterations should you run, and how often does it succeed? What about N = 16?

N = 4: sin θ = 1/2, so θ = 30°. One iteration gives 3θ = 90°: success every time. N = 16: sin θ = 1/4, θ ≈ 14.48°, π/(4θ) ≈ 3.1, so t = 3 and P = sin²(7θ) ≈ 0.961.
Module 2 · Grover's search14

More than one marked item

s marked

sin θ = √(s/N). Compose one oracle per string. s = 2 of N = 8: θ = 30°, so one iteration finds a marked item with certainty (lab Step 7).

Half marked

s = N/2 gives θ = 45°: one iteration leaves the success probability at 1/2. Guessing already does that well, so Grover does not help.

s unknown

If you do not know s, choosing the number of iterations at random still finds a marked item with good probability, using about √N queries. The optional video clip explains why.

Module 2 · Grover's search15

A quadratic speed-up

  • About √N oracle calls instead of about N: a quadratic speed-up, not an exponential one.
  • No quantum algorithm can do unstructured search with fewer than about √N queries, so Grover's search is optimal up to a constant factor.
  • The speed-up counts oracle calls. On real hardware each call is a circuit with many gates, and noise limits how many iterations you can run. Module 4 measures this cost.
